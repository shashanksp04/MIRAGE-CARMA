# Related Work

## Agricultural Multimodal Question Answering

AgMMU and MIRAGE both connect agricultural images with domain knowledge, but they emphasize different forms of evaluation. AgMMU is derived from grower--Cooperative Extension dialogues and pairs multiple-choice and open-ended evaluation questions with AgBase, a development corpus spanning identification, symptoms, disease categories, and management instructions [@gauba2025agmmu]. The agricultural MIRAGE benchmark moves toward the structure of an expert consultation. Its single-turn task pairs natural user questions with one or more user-supplied images and metadata and asks for entity identification, causal explanation, or management guidance; its broader benchmark also includes multi-turn clarify-or-respond decisions [@dongre2025mirage]. MIRAGE is especially relevant here because its contextual questions may be underspecified: place, time, or other context used by an expert need not appear explicitly in the question text.

Agricultural multimodal RAG has also been studied directly. Liu et al. combine a trained lightweight multimodal prompt-generation model, a fruit-tree knowledge base and RAG, and complexity-based routing among language models of different scales [@liu2026agriqa]. Their focus is a domain-optimized model and resource-allocation policy for fruit-tree diagnosis. The present work is instead designed to evaluate a general multimodal answer model on MIRAGE while varying how a separate text-evidence stage selects and acquires agricultural passages; it does not train a new vision encoder.

It is distinct from both the agricultural MIRAGE benchmark [@dongre2025mirage] and the e-commerce system named MIRAGE introduced by Sahay et al. [@sahay2026ecommercemirage]. We therefore use *MIRAGE* alone only for the agricultural benchmark.

## Multimodal Language Models and Knowledge-Intensive VQA

Modern vision--language models commonly connect pretrained visual and language components and then adapt the resulting system for open-ended interaction. Flamingo inserts gated cross-attention layers into a language model and supports prompts containing interleaved text and multiple images [@alayrac2022flamingo]. BLIP-2 instead learns a lightweight querying transformer between a frozen image encoder and a frozen language model [@li2023blip2], while LLaVA uses visual instruction tuning to connect a vision encoder with a language model for general-purpose image--language instruction following [@liu2023llava]. These architectures establish a flexible generation interface, but that interface does not by itself specify where task-dependent external knowledge should come from.

Knowledge-intensive visual question answering makes this distinction explicit. OK-VQA was constructed so that image content alone is insufficient to answer its questions [@marino2019okvqa]. EnFoRe follows a two-stage pattern in which a model first retrieves textual knowledge and then answers with a VQA model; it uses question-relevant entities to make retrieval more specific [@wu2022enfore]. Lin and Byrne instead jointly train differentiable dense passage retrieval and answer generation for outside-knowledge VQA [@lin2022retrieval]. MuRAG broadens the retrieval target itself by learning to retrieve from a multimodal memory containing images and text [@chen2022murag].

The present architecture follows the established modular, two-stage pattern rather than claiming that decomposition as novel. Its evidence controller is text-only and retrieves text passages; it neither receives the user's images nor retrieves images from the knowledge collection. The downstream generator alone receives the user-supplied images together with the question and any returned passages. This boundary allows the evidence policy and textual knowledge source to vary without retraining the multimodal answer model, but it cannot acquire additional visual evidence in the manner of MuRAG.

## Retrieval-Augmented Generation and Retrieval Scope

Retrieval-augmented generation combines a generator's parametric knowledge with passages selected from an external collection [@lewis2020rag]. Dense retrievers encode queries and passages into a shared vector space, providing a semantic matching signal without requiring exact lexical overlap [@karpukhin2020dpr]. Fixed-dimensional dense representations nevertheless have capacity limits for precise retrieval of long documents, and sparse, dense, and attentional signals offer different retrieval characteristics [@luan2021sparse]. When applicability depends on an exact source attribute, metadata filtering provides a different signal from semantic proximity.

Multi-Meta-RAG uses language-model-extracted metadata as database filters when selecting documents for multi-hop questions [@poliakov2025multimetarag]. Time-aware agricultural retrieval provides a still closer comparison. TARAG constructs a time-annotated crop pest and disease knowledge base, combines sparse and dense retrieval with time-sensitive reranking, and conditions agricultural suggestions on the resulting passages [@liu2026tarag]. Its temporal representation models agricultural entities, phenological stages, pest life stages, and related time expressions. The present implementation uses a more limited exact `month_year` payload field with mixed source-date and acquisition-date provenance; it does not model phenology or biological stage.

Metadata can also structure multimodal retrieval itself. The e-commerce MIRAGE system projects troubleshooting text and images into a shared schema of product attributes, context, and visual aspects, then uses that schema to link visual content and condition answer generation [@sahay2026ecommercemirage]. In contrast, the present system applies exact payload constraints only to textual passages and performs no image retrieval. Its metadata describes agricultural scope rather than visual product attributes.

Within the proposed retriever, a plant-hardiness zone is deterministically derived from available location metadata. `month_year` and `title` are optional arguments supplied by the tool-using controller in a retrieval call; the driver does not independently serialize MIRAGE's asked-time field into `month_year`. The retriever constructs every eligible combination from a predefined family of hardiness-zone, month--year, and title constraints, searches each candidate scope, and selects a nonempty candidate set under a common score. Semantic-only retrieval is always eligible and is evaluated alongside the applicable filtered scopes. Missing fields therefore remove only the combinations that require them.

This procedure differs from conventional sparse--dense hybrid retrieval. Sparse--dense systems combine lexical and embedding-based relevance signals [@luan2021sparse], whereas the proposed retriever combines exact structured filtering with dense semantic ranking. Hardiness zone supplies a climate-derived geographic proxy; it does not establish shared regulations, pest incidence, or institutional jurisdiction between locations.

## Adaptive, Reflective, and Corrective RAG

A fixed retrieve-once pipeline spends the same retrieval effort regardless of the question and has no explicit response when its first evidence set is weak. Several lines of work make retrieval conditional. FLARE monitors confidence in upcoming generated content and retrieves iteratively when low-confidence tokens occur [@jiang2023flare]. Adaptive-RAG selects among no-retrieval, single-step, and iterative strategies using a learned question-complexity classifier [@jeong2024adaptiverag]. Self-RAG trains a language model to emit reflection tokens that govern retrieval and critique retrieved passages and generated claims [@asai2024selfrag]. These methods place the adaptation signal at different points---during generation, before retrieval, or within a learned reflective policy.

Corrective RAG focuses more directly on evidence quality. CRAG applies a retrieval evaluator to an initially retrieved set, triggers different corrective actions from its confidence estimate, and can extend a limited static corpus with web search [@yan2024crag]. The proposed system adopts a related corrective pattern, but its confidence evaluation is a fixed routing heuristic over mean retrieval similarity, hit count, score dispersion, and selected metadata scope. It is neither trained as a correctness estimator nor calibrated as a probability. The resulting label informs a prompt-directed tool policy, so the heuristic itself is deterministic while compliance with the multi-step repair sequence depends on the controller model.

## Dynamic Web Augmentation

WebGPT demonstrated browser-assisted question answering in which a model searches and navigates web pages while collecting supporting references [@nakano2021webgpt]. CRAG uses web search more specifically as a corrective source when its retrieval evaluator judges static-corpus evidence inadequate [@yan2024crag]. The proposed web branch likewise addresses evidence outside the curated collection, but acquired pages are extracted, chunked, embedded, and stored in a run-scoped runtime collection rather than added to the read-only base.

An optional search restriction uses location-linked academic domains when mappings are available. The controller is instructed to request web acquisition only after low retrieval confidence and to retrieve again after ingestion. Because the runtime collection is shared within a run, newly acquired evidence may be reused by later items. Live search results, page contents, and this cross-item state can vary with acquisition time and execution order; the experimental protocol and limitations therefore treat the search date and runtime-collection lifecycle as reproducibility variables.

## Positioning of the Proposed System

The closest work already combines several mechanisms considered here. Liu et al. integrate agricultural multimodal QA, domain RAG, and complexity-based model routing [@liu2026agriqa]; TARAG combines agricultural temporal metadata with hybrid retrieval and time-aware generation [@liu2026tarag]; and the e-commerce MIRAGE system uses structured metadata for multimodal retrieval and generation [@sahay2026ecommercemirage]. Against these comparators, the proposed architecture is defined by a different combination: it compares all eligible exact agricultural metadata scopes with an always-eligible semantic-only scope, applies a deterministic and explicitly uncalibrated retrieval-confidence heuristic, isolates online ingestion in a run-scoped collection, and supplies only textual retrieved evidence to a multimodal answer model.

The implemented code provides these mechanisms and candidate configurations. The planned evaluation will use the agricultural MIRAGE benchmark to compare supported configurations once the authoritative condition matrix, launch bindings, run manifests, and manipulation checks are established. Accordingly, this section positions an implemented architecture and a planned controlled evaluation; it makes no claim that the ablation study has already been executed or that any mechanism improves model performance.
