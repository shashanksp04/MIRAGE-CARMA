# Unresolved Questions

These issues should remain out of manuscript prose or receive `[DETAIL REQUIRES VERIFICATION]` until resolved. They are ordered by impact on Methodology and Experimental Setup.

## Critical: current Qwen-3 experiment definition

1. **Which exact Qwen-3 model is the subject model?** The repository contains evidence for `Qwen/Qwen3-32B` only as an LLM judge. Current generation and SGLang launch files select Llama-3.2-11B-Vision-Instruct (`Inference/bash_generate.sh:18-38`; `job_scripts/3gpu_4hr_script.slurm:27-63`; `Evaluation/logs/benchmark_run_Qwen3-32B.log:1-16`). Verify the exact Hugging Face model ID, checkpoint/revision, parameter size, modality support, and whether the same model controls RAG tools, crop enrichment, keyword extraction, and final answer generation.
2. **What is the Qwen-3 serving configuration?** No current launch script establishes its SGLang/vLLM version, tensor parallelism, tool-call parser, reasoning mode, multimodal flags, context length, quantization/dtype, GPU allocation, or endpoint count. These cannot be inferred from the historical judge client.
3. **What decoding settings define the experiment?** Final generation code fixes temperature 0.8, top-p 0.95, and 4,096 output tokens (`chat_models/Client.py:32-39`), while the RAG ADK client does not explicitly set sampling parameters (`rag_agent/main.py:567-574`). Confirm whether the current Qwen-3 experiment uses these values or server overrides, and record random seeds/determinism controls.

## Critical: nine-ablation matrix and launch correctness

4. **What are all nine intended configurations?** The JSON contains only IDs 2, 3, 4, 5, 7, 8, and 9. There is a separate `--no-rag` baseline, but no configured IDs 1 or 6 and no ninth runnable condition (`rag_agent/ablation_configs.json`; `Inference/generate.py:539-583`). Obtain the authoritative nine-row matrix and exact IDs/names.
5. **How should `db_on` and `crop_dict_on` be enacted?** `MainAgent` does not read these JSON keys. Each run must currently coordinate `--use_base_collection`, `--disable_query_enrichment`/dictionary availability, and sometimes `--no-rag` outside the ablation configuration (`rag_agent/main.py:164-196`; `Inference/generate.py:850-930`). Verify the intended launcher or implement/record an authoritative mapping before claiming that one ablation ID controls every component.
6. **Is “DB off” intended to mean no curated base or no vector retrieval at all?** `--use_base_collection false` still creates and queries a runtime collection, and ID 9's prompt starts with retrieval before low-confidence web augmentation. The manuscript should distinguish “curated base disabled” from “no vector database” (`rag_agent/main.py:55-91`; `rag_agent/model_instructions.md:140-233`).
7. **Fix or supersede the checked-in inference wrapper before citing it as the experimental launcher.** It comments out `--ablation_id` and passes `base` to a boolean parser, which evaluates false (`Inference/bash_generate.sh:43-77`; `Inference/generate.py:866`). Confirm the actual per-ablation commands, output paths, and whether runtime mode is fresh for every condition.
8. **Define the controlled variables across ablations.** Confirm identical benchmark records/order, image policy, subject/RAG model, model revision, prompts except the documented control policy, embedding checkpoint, base snapshot, runtime collection freshness, web-search time window/API, generation sampling, hardware, concurrency, and retry policy.

## Critical: benchmark and evaluation

9. **Which benchmark subset is the current study using?** The repository has the full 8,188-record standard benchmark, eight-record standard/contextual samples, and assorted historical inference splits, but no full contextual benchmark. Confirm standard vs contextual scope, state/category filters, and final sample counts per condition.
10. **Resolve duplicate benchmark IDs.** Four IDs occur twice in the standard JSON. Resume logic treats IDs as unique, and `Inference/split.py` collapses duplicates into an ID-keyed dictionary (`Inference/generate.py:590-606`; `Inference/split.py:71-76`). Decide whether these are intentional alternate-image records, assign unique experimental IDs if needed, and report the post-deduplication sample count.
11. **Who is the final judge and how many judge runs are used?** Current wrapper selects Llama-3.2-11B-Vision-Instruct, while historical artifacts use Qwen3-32B. Confirm judge checkpoint, prompt version, decoding settings, number of independent judgments, aggregation, invalid-output handling, and any human validation.
12. **Confirm metric presentation.** `print_scores.py` multiplies the mean binary/ordinal identification-accuracy score by 100 but leaves reasoning accuracy as a raw mean, while management uses raw 0--4 means and a weighted normalized sum. Confirm that this is intended and define confidence intervals/significance tests before Results are written.

## Methodology details requiring confirmation

13. **Approve the system name.** “MIRAGE-CARMA” is not present in repository sources. Confirm whether it is the paper's final name and how it relates to MIRAGE-CARMA and MIRAGE-CARMA. The decision should also account for the unrelated e-commerce system named MIRAGE published by Sahay et al. at EACL 2026, as well as the agricultural MIRAGE benchmark.
14. **Is the natural-language agent loop the intended scientific method?** The five-success/ten-attempt web-ingestion loop is enforced by the model instruction, not a deterministic controller. Confirm whether experimental traces demonstrate compliance and whether deviations are retried or excluded (`rag_agent/model_instructions.md:49-69`; `Inference/generate.py:338-364`).
15. **What exactly is persisted for audit?** Current JSONL omits tool-call sequence, retrieved chunk IDs/text, confidence scores, chosen strategy, effective enriched query, and source URLs. Confirm whether a separate logging/tracing system was used during the current experiment; otherwise, avoid stronger behavioral-logging claims.
16. **Should confidence retrieve twice?** `retrieve_content` obtains evidence and `evaluate_retrieval_confidence` independently reruns retrieval. Confirm this is intentional and stable under concurrent runtime ingestion (`rag_agent/main.py:484-536`; `rag_agent/tools/confidence_evaluator.py:76-91`).
17. **How should the dual-retriever strategy be described?** Each collection independently selects a best strategy; after merging, the reported strategy is taken from whichever collection returned more results, not from a global comparison of strategy scores (`rag_agent/utils/dual_collection_retriever.py:24-46`). This reported strategy feeds the confidence scope weight. Confirm whether this is the intended algorithm.
18. **What is the scientific provenance of confidence weights and thresholds?** The formula and thresholds are verified in code, but no calibration dataset, fitting method, or prior study is recorded. Describe them as fixed design choices unless calibration evidence is supplied.
19. **How should web-result dates be interpreted?** Missing source dates are replaced by the current month, which can make ingestion-time metadata appear to be publication time (`rag_agent/tools/web_search.py:155-171`). Confirm whether this fallback was active during experiments and whether it should be labeled as retrieval time.
20. **Is runtime PDF ingestion part of any evaluated condition?** The PDF tool is registered when the ingestion loop is on, but all current low-confidence prompt templates direct ingestion from web-search URLs. Do not imply that runtime PDF ingestion was exercised without traces.
21. **Where is the crop dictionary used for inference?** The default `Inference/CropDatabase.json` is absent. Verify the actual artifact path, version/hash, states/crops covered, and whether the current experiment mounted it externally.

## Offline corpus and reproducibility

22. **What exact base snapshot was used?** Record Qdrant snapshot name/hash, build ID, wave IDs, final point/chunk/document counts, included states, source counts/types, collection creation parameters, and build completion date.
23. **How is `mirage_base_build` promoted to `mirage_base`?** The worker and finalizer target `mirage_base_build`; inference expects `mirage_base`. No checked-in code establishes the rename/alias/restore step.
24. **Was the concurrent preload actually run to completion for the experimental corpus?** The notebooks and coordinator implement the architecture, but no completed state/wave manifests or final snapshot manifest are checked in. Manuscript prose can describe the implemented pipeline, but corpus-size and completed-build claims need artifacts.
25. **What sources and inclusion policy produced the base corpus?** Verify the precise URLs/PDFs/CSVs, states, dates, qualification acceptance rules, and licensing. The worker configuration shows the models and thresholds but not the actual completed inputs.
26. **Resolve embedding normalization details.** Runtime encodes normalized embeddings (`rag_agent/utils/Embedding.py:12-21`), while the preload worker notebook calls `model.encode(..., normalize_embeddings=False)` before cosine-distance Qdrant upsert (worker notebook cell 35). Qdrant cosine collections may normalize internally, but the exact server behavior/version and cross-path equivalence should be verified.
