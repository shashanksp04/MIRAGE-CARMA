\begin{abstract}
Agricultural questions grounded in images often require information that is not visible in the image itself. Geographic location, crop identity, season, and regional growing conditions can all determine which external evidence is relevant to a user's question. We present MIRAGE-CARMA, a context-adaptive retrieval system for multimodal agricultural reasoning. Given a question, image, and location, the system can enrich the textual query, evaluate multiple metadata-constrained retrieval strategies together with unrestricted semantic retrieval, and select the strategy that provides the strongest relevant evidence. A confidence-aware controller then determines whether the retrieved evidence is sufficient. When it is not, the system can search domain-relevant web sources, ingest newly acquired passages into a run-scoped knowledge store, and retrieve again without modifying the curated knowledge base. The demonstration exposes these intermediate decisions, allowing users to inspect how contextual metadata changes retrieval, why external acquisition is triggered, which evidence is admitted to the final context, and how newly acquired knowledge can be reused across subsequent queries.
\keywords{retrieval-augmented generation \and adaptive retrieval \and metadata-aware retrieval \and multimodal reasoning \and agriculture}
\end{abstract}

\section{Introduction}

Agricultural reasoning is strongly context dependent. An image may show visible symptoms, plant damage, or an insect, but the most relevant interpretation and management information can depend on the crop, location, season, and regional growing conditions. The MIRAGE benchmark captures this setting through multimodal agricultural questions that combine natural-language requests, one or more images, and contextual metadata~\cite{dongre2025mirage}. These tasks require more than visual recognition because the useful supporting knowledge may not be recoverable from the image alone.

Retrieval-augmented generation (RAG) provides language models with external evidence that can be updated and inspected independently of model parameters~\cite{lewis2020rag}. A conventional retrieval pipeline, however, usually searches a fixed collection using a single semantic query. Such a pipeline does not explicitly reason about whether structured context should narrow the search space, and it has no built-in response when the available evidence is weak.

Several recent systems make retrieval conditional on question difficulty or evidence quality. Self-RAG incorporates learned reflection into retrieval and generation~\cite{asai2024selfrag}, while Corrective RAG introduces an explicit retrieval-quality assessment and can fall back to web search when the initial corpus is insufficient~\cite{yan2024crag}. Metadata-aware RAG systems have separately shown that structured attributes can guide document selection~\cite{poliakov2025multimetarag}. MIRAGE-CARMA combines these ideas in a multimodal agricultural setting, with emphasis on how retrieval context is selected, evaluated, and expanded.

MIRAGE-CARMA separates textual evidence acquisition from multimodal answer generation. A text-based evidence controller receives the question and available contextual metadata, while the final vision-language model receives the question, retrieved evidence, and user-provided images. The controller can compare multiple metadata-aware retrieval strategies, assess the resulting evidence, and acquire new information when the existing knowledge stores are insufficient.

\subsection{Contextual Query Construction}

Each request contains a natural-language question, one or more images, and a state or state-and-county location when available. Location is included in the effective textual query and is also mapped to a USDA plant hardiness zone when the mapping can be resolved. Hardiness zones provide a coarse climatic signal based on average annual extreme minimum temperature~\cite{usda2023phzm}. MIRAGE-CARMA uses the resulting zone as retrieval metadata rather than as a complete representation of local agricultural conditions.

The system can also perform constrained crop-aware query enrichment. When a question implicitly refers to a crop without naming it, an enrichment model may insert a crop name drawn from a state-specific allowlist. The rewritten query is accepted only if the original question remains intact under an insertion-only validation rule. Otherwise, the original query is used.

This stage produces the effective textual query used by the evidence controller. The images themselves are not passed to the retrieval stage. They are preserved for final multimodal generation.

\subsection{Progressive Metadata Filtering}

A central component of MIRAGE-CARMA is \emph{progressive metadata filtering}. Instead of committing to a single metadata filter, the retriever evaluates several candidate strategies supported by the metadata available for the current query.

Let

\[
z=\text{hardiness zone}, \qquad
m=\text{month-year}, \qquad
t=\text{title}.
\]

The candidate strategy family is

\begin{equation}
\mathcal{A}
=
\{
z+m+t,\;
z+t,\;
t,\;
m,\;
z+m,\;
z,\;
\varnothing
\},
\label{eq:candidates}
\end{equation}

where \(\varnothing\) represents unrestricted semantic retrieval. A candidate is evaluated only when all metadata fields required by that strategy are available. Semantic-only retrieval is always eligible.

This construction is progressive in specificity, but it is not implemented as a first-success fallback. MIRAGE-CARMA evaluates every eligible candidate and compares their retrieval quality.

Questions and passages are embedded using \texttt{BAAI/bge-base-en-v1.5}. Each candidate retrieves up to \(k=5\) passages using cosine similarity. For a candidate strategy \(a\), let \(s_{a,j}\) denote the raw cosine similarity of relevant passage \(j\), and let \(n_a\) denote the number of relevant passages returned. The candidate score is

\begin{equation}
R(a)
=
\frac{1}{n_a}
\sum_{j=1}^{n_a}
\frac{1}{2-s_{a,j}}.
\label{eq:strategy-score}
\end{equation}

The selected retrieval strategy is

\begin{equation}
a^*
=
\operatorname*{arg\,max}_{a\in\mathcal{A}_{\mathrm{eligible}}}
R(a).
\label{eq:strategy-select}
\end{equation}

The nonlinear transformation in Eq.~\ref{eq:strategy-score} is used only to compare candidate strategies within a collection. The retrieved passages themselves retain their raw cosine similarities for later ranking and confidence evaluation.

Progressive retrieval is performed independently over two knowledge stores. The curated collection, \texttt{mirage\_base\_build}, contains agricultural material prepared offline and remains read-only during inference. A second Qdrant collection is created for the current run and stores evidence acquired dynamically. The selected results from the enabled collections are merged, deduplicated, ranked by raw similarity, and truncated to the final evidence budget.

This design allows structured context to constrain retrieval when it is useful while retaining unrestricted semantic retrieval as a competing strategy.

\subsection{Confidence-Aware Knowledge Acquisition}

After retrieval, MIRAGE-CARMA evaluates whether the current evidence is sufficient to continue directly to generation or whether additional information should be acquired.

Let \(S\) denote mean similarity across the relevant passages, \(V\) denote relevant-result coverage, \(K\) denote score consistency, and \(P\) denote a weight associated with the selected retrieval scope. The routing score is

\begin{equation}
C
=
0.70S
+
0.15V
+
0.10K
+
0.05P.
\label{eq:confidence}
\end{equation}

This value is a routing heuristic, not a calibrated probability that the retrieved evidence or final answer is correct. Similarity receives the largest weight, while coverage, consistency, and retrieval scope provide secondary signals.

When the resulting evidence reaches medium or high confidence, the retrieved passages are returned for generation. When confidence is low, the evidence controller is instructed to begin an acquisition branch.

The controller first extracts search-oriented keywords from the effective query. It then queries You.com and can optionally restrict the search to location-linked academic domains. These domains are derived from state-level land-grant institutions and universities associated with the relevant hardiness zone.

Retrieved web pages are processed into textual passages and written only to the mutable runtime collection. Newly acquired content never modifies the curated collection. Once ingestion is complete, the system retrieves again and reevaluates confidence using the expanded evidence store.

The resulting control flow can therefore be summarized as

\[
\text{Retrieve}
\rightarrow
\text{Evaluate}
\rightarrow
\begin{cases}
\text{Generate}, & \text{if evidence is sufficient},\\
\text{Search} \rightarrow \text{Ingest} \rightarrow \text{Retrieve again},
& \text{otherwise}.
\end{cases}
\]

The confidence calculation itself is deterministic. The multi-step acquisition branch is prompt-directed by the tool-using evidence controller rather than implemented as a fully deterministic Python state machine.

\subsection{Two-Tier Knowledge Store and Multimodal Generation}

The two-store design separates stable curated knowledge from information acquired during execution.

The curated collection is constructed offline from agricultural sources and is treated as immutable during inference. Runtime knowledge is isolated in a collection created for the current run. Web-acquired passages are embedded, deduplicated, and inserted only into this mutable store.

This separation has two purposes. First, external acquisition cannot silently alter the curated knowledge base. Second, information obtained for one query can become retrievable for later queries within the same run. The runtime collection therefore acts as reusable short-term knowledge rather than temporary text appended only to a single prompt.

After retrieval is complete, the selected textual evidence is concatenated with the effective question. The final vision-language model receives this context together with the original user images and produces the multimodal response.

This division also keeps evidence acquisition independently inspectable. The system can expose what was retrieved and why before the answer model generates its response.

\section{Implementation and Demonstration [NOT FINALIZED]}

MIRAGE-CARMA uses Qdrant for vector retrieval and runtime ingestion and \texttt{BAAI/bge-base-en-v1.5} for text embeddings. Model-facing services are exposed through an OpenAI-compatible interface. SGLang is used for local model serving, while the evidence controller is implemented through Google ADK and LiteLLM. Web acquisition uses You.com search followed by page extraction, chunking, deduplication, embedding, and runtime insertion.

The research deployment uses four NVIDIA A40 GPUs concurrently, with separate resources allocated to evidence-controller workers and final response generation. The demo preserves this separation between evidence acquisition and multimodal generation, although the public deployment may use a different hardware configuration.

The interactive demonstration is organized around the retrieval trace rather than only the final answer. A user begins with an agricultural image, question, and location. During execution, the system can expose the effective query, candidate metadata strategies, selected strategy, retrieved passages, provenance, similarity scores, confidence state, and any subsequent web acquisition.

Three behaviors are particularly useful to demonstrate. First, a user can keep the image and question fixed while changing the location, making it possible to observe how contextual metadata changes the eligible retrieval strategies and returned evidence. Second, a case with weak initial evidence can expose the complete acquisition path from low confidence to web search, ingestion, and re-retrieval. Third, a related follow-up query can retrieve evidence previously acquired into runtime memory, demonstrating that dynamically acquired knowledge is reusable within the run.

The system is currently designed around U.S. agricultural context. Plant hardiness zones are coarse climatic proxies and do not encode every variable relevant to local agricultural decisions. Live web search can also change over time, and the confidence score in Eq.~\ref{eq:confidence} is heuristic rather than calibrated. These constraints motivate the emphasis on inspectability. MIRAGE-CARMA is intended as a system for studying evidence acquisition and grounded multimodal reasoning, not as a replacement for professional agricultural diagnosis.

\section{Conclusion}

MIRAGE-CARMA demonstrates a retrieval process in which structured context influences how external knowledge is searched, evidence quality determines whether the system should continue or acquire additional information, and newly acquired knowledge remains available for subsequent retrieval.

The key idea is that metadata, confidence, and external acquisition are not treated as independent preprocessing features. They jointly control the path through which evidence reaches the final multimodal model. By exposing that path to the user, the demonstration makes it possible to inspect not only the answer produced by the system, but also which retrieval strategy was selected, why additional knowledge was sought, and how the final evidence context was assembled.
